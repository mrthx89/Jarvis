## Changes and evidence

- **A1 — mode selection:** idle mode change revokes normal ownership and explicitly displays “Paused • mode diubah, tekan Mulai untuk melanjutkan”. It does not arm a recorder. Busy capture/upload/playback/drain and dedicated ownership reject mode changes. Activity rerenders actions. `OwnershipHarness` exercises busy rejection, normal-idle transition, paused selection, sheet exclusion and foreground cycling without resume.
- **A2 — stale diagnostic operations:** `SheetOperation` admits completion only for matching operation generation, owner, expected state and capture generation. Close/release state, delete supersession, capture invalidation and new owner/capture reject stale completion. Delete fences playback immediately and waits for dismissal confirmation. `DiagnosticHarness` exercises these tickets; it is not Android playback/UI evidence.
- **A3 — transient conversation recovery:** transient socket loss persists normal microphone intent OFF and fences output without shutting down the reconnecting client/upload worker. An already-started conversation capture may finish into its bounded local buffer; enrollment and other dedicated sheet work are discarded on disconnect. No new offline capture or offline reply is promised. Reconnect queries status before replay. `unknown` enters `RETRY_READY`; the user must press Mulai within the original 30-second seal TTL, on the same server instance. Only then is `conversation_resume` requested; its matched ACK permits same-ID upload from byte zero, not a new recorder or output admission. No admission bypass or automatic resume is implemented. Accepted/completed/cancelled/rejected outcomes do not replay. Changed server instance, TTL expiry, explicit stop/background/permission/credential/endpoint changes fail closed. Connection identity is captured before asynchronous delivery so a reconnect cannot turn a pending sealed capture into a blind fresh begin. Accepted-status queries survive repeated disconnects. `UploadHarness` and `LocalCaptureHarness` exercise production Java upload/recovery/ownership seams together, including capture continuation, begin/send/commit loss, status-first explicit retry, original ID, TTL, changed instance, enrollment discard and privacy cancellation.
- **A4 — duration cap:** all three purposes retain 320000 samples and `duration_limit`. `Sealed.status()` projects the 20-second terminal reason into conversation/enrollment/diagnostic statuses, retained through subsequent status updates until a new recording. `LocalCaptureHarness` feeds synthetic PCM to the cap for each purpose and checks samples, end reason and visible status text.
