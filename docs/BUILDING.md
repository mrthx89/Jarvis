# Android builds and signing

Stage 1 was intentionally NOT built or run through Gradle/CI at the owner's request. The commands below are for the owner to run; their presence is not a claim of successful compilation. Earlier APKs predate device authentication.

## Toolchain and wrapper

Use a full JDK 17, Android SDK 34 and network access for dependency resolution. Open `android/` in Android Studio, or run commands from that directory. Wrapper files are tracked from Gradle v8.7.0, not generated by invoking Gradle here. The 8.7 distribution SHA256 is pinned in wrapper properties. Wrapper JAR SHA256 was compared against the official published checksum:

    cb0da6751c2b753a16ac168bb354870ebb1e162e9083f116729cec9c781156b8

Official checksum sources:
https://services.gradle.org/distributions/gradle-8.7-wrapper.jar.sha256
https://services.gradle.org/distributions/gradle-8.7-bin.zip.sha256

Ensure `app/google-services.json` contains a Firebase client for `id.my.yhdev.nexo` (and optionally `id.my.yhdev.jarvis` for dual compatibility). It is client configuration, not a Firebase administrator service-account credential. If missing, obtain it from the owner's Firebase console (see [docs/FIREBASE_SETUP.md](FIREBASE_SETUP.md)). `local.properties` may set the local Android SDK path; do not commit it.

## Owner test build

    ./gradlew testDebugUnitTest assembleInternal

Windows:

    gradlew.bat testDebugUnitTest assembleInternal

`internal` deliberately uses debug signing and version suffix `-internal`. Output: `app/build/outputs/apk/internal/`. It retains the production applicationId so the existing Firebase package entry remains valid. It cannot coexist with the production package or update a differently signed installation. Do not uninstall automatically: that removes app data and the encrypted device credential. Back up/provision deliberately.

## Production release

`release` no longer falls back to debug signing. Without signing environment variables it produces an unsigned release artifact, which is not installable until signed. For a signed release set all four environment variables locally using a secret manager or secure shell prompts:

    NEXO_KEYSTORE_PATH       absolute path to the owner's keystore (fallback: JARVIS_KEYSTORE_PATH)
    NEXO_KEYSTORE_PASSWORD   keystore password (fallback: JARVIS_KEYSTORE_PASSWORD)
    NEXO_KEY_ALIAS           signing alias (fallback: JARVIS_KEY_ALIAS)
    NEXO_KEY_PASSWORD        key password (fallback: JARVIS_KEY_PASSWORD)

Then run `./gradlew assembleRelease`. Never commit credentials, paste them into public logs, or put them on command-line arguments. Partial configuration fails explicitly. The previously tracked `android/Jarvis.jks`, its historical extensionless alias `android/Jarvis`, and real Firebase client configuration were removed from published branch history by a coordinated rewrite. Local physical credential files were preserved. This does not erase copies in existing clones, forks or server caches and does not rotate any key. If it was a production signing key, evaluate exposure and plan rotation/update compatibility. See [history cleanup](HISTORY_CLEANUP.md) before syncing an older clone.

## CI

`.github/workflows/verify.yml` supports `workflow_dispatch` only. Push and pull request events do not trigger builds. The workflow has NOT been run for this iteration. When manually invoked it runs Python tests and Android unit tests/lint/internal assembly, validates the wrapper, and uploads an explicitly internal debug-signed artifact. If Firebase client configuration is not tracked, set repository secret `GOOGLE_SERVICES_JSON` to its JSON contents. Production signing keys are not used in this workflow.

## Migration

Follow [DEVICE_AUTH](DEVICE_AUTH.md) before activating the new backend. Repository changes do not update the already running process. New Android compilation and actual microphone/speaker/reconnect behavior remain for owner verification. The older voice-repair verification documents apply only to their recorded pre-auth revision.
